# Plan: Writing (phase 2)

Five steps, each a PR with its own short spec page if it adds routes or contracts; the gate closes the phase.

| Step | Work | New pieces |
|---|---|---|
| 2.1 | Prompts, submission, job, results page; consent notice; per-learner limits and the cost cap | `data/writing/prompts.yaml`; migration: `essays`, `essay_results`; job kind `essay` in the queue; routes `POST /essays`, `GET /essays/{id}`; web `/viet` |
| 2.2 | Deterministic analysis; minimal correction; ERRANT types; mapping table; BKT updates | **LanguageTool** service (Java, own container), **spaCy** + **ERRANT** in the worker; `data/writing/error-map.yaml` |
| 2.3 | Scorer: candidate models evaluated on the private set, the best kept, fine-tuning if data allows | **scorer** service (PyTorch CPU, transformers), `evalkit/writing_gate.py`, a fine-tuning notebook (GPU) |
| 2.4 | LLM feedback with verified quotes; hint-first self-correction; target-band rewrite with its checks; phrases to FSRS | gateway tasks `writing_feedback`, `writing_correct`, `writing_rewrite` in `routing.yaml` |
| 2.5 | Task 1: charts from data, facts in the answer checked against the chart (`curriculum/facts.py`), feedback | Task 1 prompts with figures |
| Gate | Mapping accuracy, QWK, stability | results in `docs/v2/writing-eval.md`; the private set stays in `data/private/` |

**Services and memory.** Writing adds two services: LanguageTool (about 1–2 GB) and the scorer (DeBERTa-v3-base, about
0.7 GB of weights on CPU). Each is measured on the owner's 8 GB laptop before it is assumed to fit; heavy work
(fine-tuning) runs on a GPU notebook. Both are opt-in compose profiles like TEI until measured.

**Model calls.** All through `app/llm/gateway.py`; feedback is generated by DeepSeek. Facts are not being generated, so
there is no blind verifier; the checks are mechanical instead: quotes must be substrings, corrections must be minimal,
rewrites must pass LanguageTool, the CEFR word check and the scorer.

**Analysis lives in the worker**, never in a request (project rule): the route queues the essay and returns at once;
the page follows progress and shows the result when ready.
